## Phase Goal

ROADMAP Phase 3's `**Goal:**` line is not written in the three-slot user-story form, so it is quoted verbatim rather than restated as an invented story (same handling as plans 03-01 and 03-02):

> Visitor can read every core section of the portfolio — Hero, Dossier, Tech Stack, Projects, Contact — matching the prototype's visual design and reflowing correctly on mobile.

This plan delivers the final vertical slice — the Projects grid, the only section backed by a Content Collection — and closes the phase's responsiveness and visual-fidelity requirements.

<objective>
Insert the Projects section between Tech Stack and Contact, rendering the `projects` Content Collection with featured-first ordering, build-optimised cover images, a gradient fallback for entries with no image, and tab-nabbing-safe external links. Add the one new CSS primitive the fallback's hover state needs, close the Phase 3 gate with a cross-section fidelity group, and confirm the finished page against the prototype with a human review.

Purpose: Projects is the section that proves the claims the rest of the page makes. It is also the only section driven by a repeating data source, so it is the only one where card count, ordering and per-entry optional fields have to be right rather than merely present. Closing the fidelity group here — after all five sections exist — is the first moment LAY-01 and LAY-02 can actually be asserted end to end.
Output: an extended `scripts/verify-sections.mjs`, one new hover primitive in `global.css`, a complete five-section `src/pages/index.astro`, and a human-confirmed visual match against `screen.png`.
</objective>

<constraints>
**Do NOT add `grid-auto-flow: dense` to the Projects grid.** A featured card spanning two of three columns leaves its row's trailing cell empty. That is CSS Grid's default sparse placement and it is the correct behaviour here: `dense` backfills gaps by reordering items, which would silently break D-07's featured-first *visual* ordering the first time a non-featured card got packed ahead of a featured one.

**Do NOT render cover images as a CSS `background-image`.** The prototype's `<div style="background-image: url(...)">` shape is structurally incompatible with `<Image>`, which emits a real `<img>`. PROJ-04 requires the `astro:assets` pipeline. Use `<Image>` styled with `w-full h-48 object-cover`; the `grayscale group-hover:grayscale-0` reveal applies identically to an `<img>`.

**Do NOT pass a possibly-undefined value to `<Image src>`.** `coverImage` is optional and is `undefined` for every entry today. `<Image>` validates props at build time and fails loudly. Render `<Image>` only inside the truthy branch of a conditional on `project.data.coverImage`.

**Do NOT add an `altText` / `coverAlt` field to the collection schema.** A schema change is outside this phase's authorised scope. Derive the `alt` value from `project.data.title` as specified in the action.

**Do NOT use `bg-gradient-to-*`.** Tailwind v4 renamed the linear-gradient direction utilities to `bg-linear-to-*`. The old name matches no utility in v4 and is silently dropped from the compiled CSS — a flat, un-gradiented panel with no build error. This is the single sharpest porting trap in this phase.

**Do NOT use `rounded-DEFAULT`, `font-mono-code`, `text-mono-code`, `font-body-lg`, `text-body-lg` or `font-bold`.** Same prototype-fidelity corrections plans 03-01 and 03-02 applied.

**Do NOT append the Projects section at the end of `index.astro`.** It goes between the Tech Stack section's closing tag and the Contact section's opening tag, so the final section order is Hero → Dossier → Tech Stack → Projects → Contact.

**Do NOT install a sorting utility library.** The featured/order sort is four lines of `.filter()` and `.sort()` with no reuse need anywhere else in this one-page site.

**Do NOT build a "safe external link" wrapper component.** There are at most a handful of external-link call sites in this phase; apply `rel="noopener noreferrer"` directly on each anchor, matching the Footer's Phase 2 precedent and plan 03-02's Contact section.

**Do NOT add a `<script>` or a `client:` directive.** The gradient-fallback hover is pure CSS.

**Do NOT touch `src/data/site.ts`, `src/content.config.ts`, `src/content/projects/`, `src/layouts/Base.astro`, `src/components/`, or `package.json`.**

**Do NOT install any npm package.**
</constraints>
