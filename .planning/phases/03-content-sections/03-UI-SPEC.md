# Phase 3 — UI Design Contract

> Visual and interaction contract for the five core content sections (Hero, Dossier, Tech Stack, Projects, Contact). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: `src/pages/index.astro` (replacing Phase 1's pipeline-proof placeholder content) + a `contactHeading`/`contactSubtitle` addition to `src/data/site.ts` + one new CSS primitive in `src/styles/global.css` for the project-card gradient-fallback hover state + a layout wrapper addition to `src/layouts/Base.astro`'s `<main>` (see Layout & Structure Contract). Does NOT touch Nav/Footer content (Phase 2, done) or SEO/404/security headers (Phases 4-5).

## Typography

Reuses all 7 DESIGN.md type roles already wired in Phase 1's `@theme`. This phase is the first to render `body-lg`, `body-md`, and `display-lg`/`display-lg-mobile` in actual content (Phase 2's nav/footer only used `mono-label`/`headline-md`).

| Role | Size | Weight | Line Height | Usage this phase |
|------|------|--------|-------------|-------|
| `display-lg` / `display-lg-mobile` | 72px desktop / 40px mobile | 700 | 80px / 48px | Hero H1 (`site.heroHeading`) — `md:font-display-lg md:text-display-lg` desktop, `font-display-lg-mobile text-display-lg-mobile` mobile-first |
| `headline-md` | 32px | 600 | 40px | All 4 section H2s (DOSSIER/TECH STACK/PROJECTS/Contact heading), Project card titles (`text-xl` override — see note below) |
| `body-lg` | 18px | 400 | 28px | Hero paragraph (`site.heroSubtitle`) |
| `body-md` | 16px | 400 | 24px | Dossier bio paragraphs (`site.bio[]`), Project card descriptions (`text-sm` override — see note), Contact subtitle |
| `mono-label` | 14px | 500 | 20px | Hero title line (`site.title`, uppercase/wide-tracking), System Specs heading, Tech Stack category headings, Project live/repo link text |
| `mono-code` | 13px | 400 | 20px | Availability badge text, System Specs list items, Tech Stack badges, Project tag pills |

Template-standard mapping (checker's generic 4-role comparison): **Body** = `body-md` · **Label** = `mono-label` · **Heading** = `headline-md` · **Display** = `display-lg`/`display-lg-mobile`.

**Deviation note (same acceptance as Phase 1):** 7 sizes / up to 4 weights (400/500/600/700) appear across this phase, exceeding the generic "2 weight / 3-4 size" heuristic. Accepted because DESIGN.md's type scale is an already-approved external contract (LAY-02 requires exact fidelity) — this is not a phase-local typography decision to simplify.

**Prototype-fidelity corrections carried into this phase (same class of fix as Phase 2's nav-brand `font-bold` removal):**
- Project card title uses `text-xl` as a Tailwind override layered on top of `headline-md` in the prototype (`code.html` line 334: `font-headline-md text-headline-md text-white text-xl`) — this is a real, intentional prototype pattern (shrinking the 32px headline-md token down for card-scale titles via `text-xl`, 20px), not a conflict like Phase 2's `font-bold` case. Port verbatim: `class="font-headline-md text-headline-md text-white text-xl"`.
- Project card description uses `text-sm` as an override on `body-md` (`code.html` line 335) — same pattern, intentional card-scale shrink. Port verbatim: `class="font-body-md text-body-md text-on-surface-variant text-sm"`.

## Layout & Structure Contract

*(Supplementary section — this phase's core deliverable is porting 5 sections of structured content, so the fixed template categories above don't fully capture section-by-section layout. All patterns below are verified, ready-to-use code from `03-RESEARCH.md` Patterns 1-7 — this section locks them as the design contract, resolving every "Claude's Discretion" item CONTEXT.md deferred to this researcher.)*

### `<main>` wrapper (resolves RESEARCH.md Open Question 1)

`Base.astro`'s current `<main id="main-content" class="relative z-10 pt-32">` has no horizontal-margin/max-width/section-rhythm wrapper. **Locked decision: add it directly to `Base.astro`'s `<main>` element**, matching the prototype's actual structure (`code.html` line 246) and avoiding future duplication when Phase 4's 404 page needs the same container:

```
<main id="main-content" class="relative z-10 pt-32 pb-section-gap px-margin-mobile md:px-gutter max-w-container-max mx-auto space-y-section-gap">
```

This is a one-line class addition to an existing element, not new nav/footer content — it does not violate CONTEXT.md's "does NOT touch the nav/footer shell" boundary (that boundary concerns Nav/Footer components' own content, not `<main>`'s layout plumbing). All 5 sections in `index.astro` render as direct children of this wrapper with no additional per-section margin/max-width wrapping needed.

### Section order & anchors

Hero (no `id`, first section) → Dossier (`id="dossier"`) → Tech Stack (`id="stack"`) → Projects (`id="projects"`) → Contact (`id="contact"`). Every `id`-bearing section carries `class="scroll-mt-32"` so the fixed nav doesn't cover the heading on anchor-jump — must match Phase 2's nav anchors exactly (already verified identical).

### Hero (HERO-01, HERO-02)

Three-level text hierarchy, top-to-bottom: availability badge → H1 (`site.heroHeading`) → title line (`site.title`) → paragraph (`site.heroSubtitle`) → CTA. Full markup: RESEARCH.md Pattern 1 (verbatim, with the CTA label changed to "VER PROJETOS" per the Copywriting Contract above). Availability badge pulse: Tailwind's built-in `animate-pulse` utility on the dot span — zero custom CSS, zero JS (D-04).

### Dossier (DOSS-01, DOSS-02)

8/4 column split (`grid-cols-1 md:grid-cols-12`, bio panel `md:col-span-8`, System Specs panel `md:col-span-4`). Full markup: RESEARCH.md Pattern 2 (verbatim). Bio renders `site.bio[]` as one `<p>` per array entry; System Specs renders `site.systemSpecs[]` as label/value rows.

### Tech Stack (TECH-01, TECH-02)

Fixed 3-column category grid (`grid-cols-1 md:grid-cols-3`) — NOT a generic loop over arbitrary categories, exactly 3 fixed cards: Languages, Frameworks, Infrastructure, reading `site.techStack.{languages,frameworks,infrastructure}`. Full markup: RESEARCH.md Pattern 3 (verbatim). Each tech renders as a monospace badge: `[ {TECH.toUpperCase()} ]`.

### Projects grid (PROJ-01–04, D-05–D-09)

Always 3 columns on desktop (`md:grid-cols-3`) regardless of entry count (D-05). Sort: `getCollection('projects')` split into `featured.sort(byOrder)` + `rest.sort(byOrder)`, concatenated featured-first (D-07). Featured cards get `md:col-span-2` + `.border-glow-cyan` (D-06); non-featured cards get `hover:border-primary-container/50`. Full markup: RESEARCH.md Pattern 4 (verbatim).

**Sparse-grid gap is intentional, not a bug:** a featured card leaves its row's trailing cell empty (CSS Grid's default `grid-auto-flow: row`, non-`dense`). Do NOT add `grid-auto-flow: dense` — it would reorder cards and violate D-07's featured-first visual contract. See RESEARCH.md Pattern 4's full explanation.

**Cover image (PROJ-04):** `<Image>` from `astro:assets`, only inside the truthy branch of `project.data.coverImage ? <Image ...> : <gradient fallback>` — never pass a possibly-`undefined` `src`. Styled `w-full h-48 object-cover` with `grayscale group-hover:grayscale-0` (photo-reveal hover, reserved for real photos per D-09).

**Gradient fallback (D-08, D-09) — locked concrete composition, resolving CONTEXT.md's discretion items:**

```html
<div class="cover-fallback w-full h-48 border-b border-outline-variant/30 flex items-center justify-center bg-linear-to-br from-primary-container/15 via-surface-container to-surface-container-high transition-all duration-500">
  <Icon name="material-symbols:code" class="cover-fallback-icon w-12 h-12 text-primary-container/60 transition-all duration-500" />
</div>
```

- Gradient direction: `bg-linear-to-br` (top-left → bottom-right) — **not** `bg-gradient-to-br` (Tailwind v3 syntax, renamed in v4; see RESEARCH.md Pitfall 1 — using the old name silently produces no gradient)
- Color stops: `from-primary-container/15` (subtle cyan tint, top-left) → `via-surface-container` → `to-surface-container-high` (neutral, bottom-right) — reuses existing palette tokens, no new colors
- Icon: `material-symbols:code` (generic "code" glyph — the same icon already used for Contact/Repo elsewhere, reinforcing the "developer artifact" visual language), `w-12 h-12` (48px), `text-primary-container/60` (60% opacity cyan, subdued so it doesn't compete with real cover photos elsewhere in the grid)
- **Hover treatment (D-09, subtle, not a full effect swap)** — add this new primitive to `global.css`:
  ```css
  .group:hover .cover-fallback {
    background-color: rgba(0, 240, 255, 0.03);
  }
  .group:hover .cover-fallback-icon {
    opacity: 1;
    transform: scale(1.08);
  }
  ```
  Effect: icon opacity lifts from 60% to 100% and scales up 8% (`scale-105`-equivalent), plus a barely-visible cyan wash overlays the gradient — noticeably "alive" on hover without approximating the reserved grayscale→color photo-reveal effect (D-09 explicitly reserves that specific effect for real photos only).

**External links (PROJ-03):** every `liveUrl`/`repoUrl` `<a>` carries `rel="noopener noreferrer"` unconditionally — applied per-link inline, not via a wrapper component (RESEARCH.md "Don't Hand-Roll" table — only ~6 external-link call sites total in this phase, a wrapper adds indirection with no DRY benefit at this scale).

### Contact (CONT-01, D-10–D-13)

Full markup: RESEARCH.md Pattern 6 (verbatim). Reuses `site.socials` exactly as Footer does (D-10) — do NOT add separate `contactEmail`/`contactGithub`/`contactLinkedin` fields. Circular icon-button treatment (`w-12 h-12 rounded-full`, D-11) — visually distinct from Footer's plain text-link row, both read the same `site.socials[].icon`/`.href`/`.label`. Every social `<a>` carries `rel="noopener noreferrer"` (D-13) and `aria-label={s.label}` (no visible text on these icon-only buttons).

`site.ts` addition required (D-12):
```typescript
// Contact section invitational copy (CONT-01, D-12).
contactHeading: "PLACEHOLDER — título do convite a definir",
contactSubtitle: "PLACEHOLDER — subtítulo do convite a definir",
```

### Mobile reflow (LAY-01)

No new tokens/CSS beyond the `<main>` wrapper above:
- 20px margins: inherited from `px-margin-mobile` on `<main>` (see wrapper section)
- Adaptive grid: every grid in this phase already uses `grid-cols-1 md:grid-cols-N` (Dossier 12-col, Stack 3-col, Projects 3-col) — standard responsive utilities, no custom breakpoint
- Reduced background grid: already implemented, Phase 1's `.bg-grid-pattern` `@media (max-width: 768px)` rule — no change needed, just confirm `Base.astro`'s `<body>` still carries `bg-grid-pattern` (it does)

### Prototype-fidelity corrections (LAY-02)

- **`rounded-DEFAULT` is not a real Tailwind class in this project** (already flagged Phase 1/2) — every instance in `code.html`'s sections (badge, button, panels, tag pills) must use bare `rounded` instead. Applies throughout Hero/Stack/Projects markup.
- **`bg-gradient-to-*` → `bg-linear-to-*`** (Tailwind v4 rename) — only relevant to the new gradient-fallback composition above; no other gradients exist in this phase's ported markup.
- **Cover images use `<Image>` (real `<img>`), never CSS `background-image`** — structurally required for `astro:assets` (PROJ-04); the prototype's `<div style="background-image:...">` pattern must not be ported verbatim (RESEARCH.md Pitfall 8).
