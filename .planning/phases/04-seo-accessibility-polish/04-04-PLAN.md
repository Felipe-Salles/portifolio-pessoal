**As a** technical recruiter (or a search-engine crawler), **I want to** find this portfolio in search, see a proper preview when its link is shared, and navigate it without accessibility barriers, **so that** the site earns technical trust before a single project description is read.

  <action>
    Extend `scripts/verify-a11y.mjs` with the supplementary contrast check that resolves the deferred entries from Task 1. axe reports `incomplete` rather than pass/fail on these elements because its ancestor-background algorithm cannot composite multiple stacked non-opaque layers plus `backdrop-filter` — treating that as a pass would make A11Y-04 vacuous, and treating it as a failure would block on a false positive, so resolve it by measurement.

    For each deferred element: obtain its `boundingBox()`, screenshot the page clipped to that box, and use `sharp` to extract a single raw RGB pixel from a position inside the element's box but outside the glyph strokes — a small inset from the top-left corner (about 2px in on each axis) is the documented choice, since text is centered or baseline-aligned and the corner is background. Read the element's own painted text color with `evaluate(el => getComputedStyle(el).color)`, convert both the sampled background and that computed color to hex, and compute the ratio with `hex()` from `wcag-contrast`.

    Apply the WCAG AA threshold by text size, not a single constant: 3.0 for large text (computed `font-size` of at least 24px, or at least 18.66px when the computed `font-weight` is 700 or greater), 4.5 otherwise. Read both computed values from the element rather than inferring from class names. A ratio below the applicable threshold is a gate violation reported as `verify-a11y: contrast — <route> <selector> ratio=<n> required=<n> fg=<hex> bg=<hex>`; a ratio at or above it marks the deferred entry resolved and increments both `incomplete_resolved` and `contrast_checked`.

    Any deferred entry that cannot be measured — no bounding box, zero-area clip, or an unreadable computed color — is a violation, never a silent skip. At the end, assert `incomplete_resolved` equals the number of deferred glass-panel entries, so an entry can never fall through unaccounted.

    If a real contrast violation appears, do not adjust any design token to silence it: 04-UI-SPEC.md's A11Y-04 section makes token changes a decision to escalate back to CONTEXT.md/UI-SPEC, not something to patch here. Report the measured numbers in the plan SUMMARY instead. RESEARCH.md Pitfall 5's hand computation predicts everything clears AA, with `btn-primary`'s 4.58:1 as the tightest margin and the first thing to re-check if this gate ever regresses.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| axe results → gate verdict | axe returns three outcomes (pass/violation/incomplete); collapsing the third into "pass" silently voids A11Y-04 |
| Build script → local network | The gate binds a preview server on localhost:4326 and drives a headless browser against it |
| Headless browser → built site JS | Chromium executes the built site's own scripts (the Phase 2 nav overlay controller) during the scan |
| Gate failure → design tokens | The cheapest way to make a contrast failure disappear is to edit a color token, which would silently break the approved design contract |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04-01 | Tampering | axe `incomplete` results treated as passes, making the A11Y-04 gate vacuous | mitigate | Every incomplete entry is either routed into the pixel-sampling contrast check or fails the gate outright; the summary line publishes `incomplete_total` and `incomplete_resolved`, and the script asserts the resolved count equals the deferred count so nothing falls through. |
| T-04-04-02 | Denial of Service (local/CI) | Orphaned preview server on port 4326 or an orphaned headless Chromium after a failed scan | mitigate | Astro's programmatic `preview()`/`stop()` plus `browser.close()` in a `finally` block; acceptance criteria re-bind port 4326 and re-run the whole script to prove release. |
| T-04-04-03 | Tampering | Headless Chromium executing the built site's JavaScript during the scan | accept | The only content loaded is this repository's own build output on localhost — no third-party, remote, or user-supplied content. The browser is discarded after each run. |
| T-04-04-04 | Tampering | Silencing a real contrast failure by editing a design token or disabling an axe rule | mitigate | Task 2 forbids token edits (04-UI-SPEC.md's A11Y-04 section escalates such changes back to CONTEXT.md/UI-SPEC); Task 1 forbids adding a rule-disabling escape hatch and requires evidence in the SUMMARY instead; an acceptance criterion asserts `src/styles/global.css` is untouched. |
| T-04-04-05 | Information Disclosure | A future contributor sending page content to a hosted accessibility-audit SaaS | mitigate | The gate is fully local build tooling: a localhost preview server plus a local Chromium, no outbound request, and none of its code ships to the browser. |
| T-04-04-SC | Tampering | npm/pip/cargo installs | accept | This plan installs no packages; `playwright`, `@axe-core/playwright`, `sharp` and `wcag-contrast` were installed and audited in plan 04-01 (RESEARCH.md Package Legitimacy Audit, 6/6 `OK`). |
