## Phase Goal

**As a** technical recruiter (or a search-engine crawler), **I want to** find this portfolio in search, see a proper preview when its link is shared, and navigate it without accessibility barriers, **so that** the site earns technical trust before a single project description is read.

This plan delivers the two visitor-facing surfaces of that story that do not exist yet: the branded 404 a mistyped URL lands on, and the share-preview image that renders when the link is pasted anywhere.

<objective>
Add the custom 404 page (A11Y-02) and the Open Graph share image pipeline (SEO-02). The 404 reuses the shared layout verbatim — full nav with cross-page anchors, footer, glass panel, `btn-primary` CTA. The OG image is produced by screenshotting an internal, `noindex`, fixed-1200x630 Astro page that reuses the real Hero classes, so the preview can never drift from the live design and always reads its text from `site.ts`.

Purpose: closes the two remaining "what does a visitor/unfurler actually see" gaps in this phase. Plan 04-01 already emitted the `og:image` meta tags pointing at `/og-image.png`; this plan makes that file real.
Output: `src/pages/404.astro`, `src/pages/og-template/index.astro`, `scripts/generate-og-image.mjs`, a committed `public/og-image.png`, and the `build` script chained to regenerate it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dist/ → public crawlers | `/og-template/` becomes a physically reachable route on the deployed static site |
| Build script → local network | The generator binds a preview server on localhost:4325 and drives a headless browser against it |
| Headless browser → built site JS | Chromium executes whatever scripts the built `/og-template/` page contains |
| Generated binary → git | `public/og-image.png` is a committed build artifact that changes whenever `site.ts` content changes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Information Disclosure | `/og-template/` internal build route reachable and indexable in production | mitigate | `<meta name="robots" content="noindex">` in the route's own head (Task 2) plus the `sitemap({ filter })` exclusion from plan 04-01; plan 04-03's gate asserts both, so a regression fails the build. |
| T-04-02-02 | Denial of Service (local/CI) | Orphaned preview server holding port 4325, or an orphaned headless Chromium process, after a failed screenshot | mitigate | Use Astro's programmatic `preview()`/`server.stop()` instead of `spawn`, and put `server.stop()` + `browser.close()` in a `finally` block. Acceptance criteria re-bind port 4325 after the run to prove it was released. |
| T-04-02-03 | Information Disclosure | A future contributor swapping local rendering for a hosted OG-image SaaS would ship site content to a third party | mitigate | The script's contract comment states generation is build-time-local only; the sole network origin is the localhost preview server; `verify:sec01` keeps external origins out of `dist/`. RESEARCH.md's Anti-Patterns section records the rejection of serverless/`@vercel/og` approaches (also incompatible with `output: "static"`). |
| T-04-02-04 | Tampering | `dist/og-image.png` missing in a build environment without a Chromium binary would silently ship a broken share preview | mitigate | The script writes the PNG to `public/og-image.png` (committed), so `astro build` copies a valid asset even when the screenshot step cannot run; the script also hard-fails (exit nonzero) rather than warning. | T-04-02-05 | Tampering | Headless Chromium executing page JavaScript during capture | accept | The only content loaded is this repository's own build output on localhost — no third-party, remote, or user-supplied content. The browser instance is discarded immediately after the screenshot. |
| T-04-02-SC | Tampering | npm/pip/cargo installs | accept | This plan installs no packages; all dependencies were installed and audited in plan 04-01 (RESEARCH.md Package Legitimacy Audit, 6/6 `OK`). |
</threat_model>
