# Phase 4 — UI Design Contract

> Visual and interaction contract for discoverability/share-preview artifacts (favicon, OG image), the custom 404 page, and the decorative-icon/aria-hidden accessibility pass. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: `src/pages/404.astro` (new page), `src/pages/og-template/index.astro` (new, internal-only screenshot target), `src/layouts/Base.astro` `<head>` additions (meta description, OG/Twitter tags, favicon `<link>`s, `aria-hidden` on the two `glow-cloud-*` divs), `src/pages/index.astro` (decorative-icon `aria-hidden` additions only — no content/layout change), three new static icon assets in `public/` (`favicon.svg`, `favicon.ico`, `apple-touch-icon.png`), one build-generated static asset (`og-image.png`). Does NOT touch Nav/Footer content (Phase 2, done), the five content sections' visible markup (Phase 3, done — this phase only adds `aria-hidden` attributes to two already-existing decorative icons within them), or production security headers (Phase 5).

Project's named tokens (unit 8px base), reused verbatim from Phases 1–3 — no new tokens needed this phase:

|-------|-------|-------|
| xs | 4px | Not used directly this phase |

| lg | 24px | Not used directly this phase (404 panel uses the `p-12`/`2xl` treatment below, matching the Contact panel's existing precedent) |
| xl | 32px | 404 CTA button horizontal padding (`px-8`), spacing below the "ERRO 404" label above the H1 |

Exceptions (all already-approved patterns from prior phases, not new deviations):
- `min-h-[60vh]` on the 404 page's centering wrapper — a viewport-proportional value, same exception class as Phase 3's Hero `min-h-[716px]` (a min-height constraint, not a margin/padding/gap value)

- Favicon assets: fixed pixel dimensions dictated by browser/OS convention, not the spacing scale — `favicon.svg` (scalable, authored at a 24×24 viewBox matching Material Symbols' own grid for visual consistency with the rest of the icon set), `favicon.ico` (multi-res: 16×16/32×32/48×48 embedded in one file), `apple-touch-icon.png` (180×180, the current iOS home-screen-icon standard size).

## Color

60/30/10 split, same base palette as Phases 1–3 — this table lists the phase-specific reserved-for elements only.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#111417` (`background`/`surface`) | 404 page canvas (inherited from `Base.astro`'s `<body>`, unchanged) + OG template canvas (same `bg-background bg-grid-pattern` treatment as the live page) |
| Secondary (30%) | `rgba(20,27,34,0.6)` glass fill (`.glass-panel`) | 404 panel background (reuses the Contact panel's exact treatment: `glass-panel ... rounded-xl ... border-glow-cyan`) |
| Accent (10%) | `#00f0ff` (`primary-container`) | See explicit reserved-for list below |
| Destructive | not applicable | No destructive actions in this phase (no forms, no delete actions — same as every prior phase) |

**Accent (`primary-container` #00f0ff) reserved for — explicit closed list, nothing outside it gets cyan:**
- 404 "ERRO 404 — ROTA NÃO ENCONTRADA" label text color (mirrors the Hero availability-badge's `text-primary-container` treatment)
- 404 panel `.border-glow-cyan` border (identical primitive to the Contact panel, Phase 3)
- 404 CTA "VOLTAR AO INÍCIO": solid cyan fill (`bg-primary-container`) + hover glow (reuses `.btn-primary:hover`, same primitive as the Hero CTA)
- OG template: every cyan element the live Hero already uses (availability-badge dot + text, title-line text, CTA fill) — the template is a direct reuse of Hero markup/classes, not a new composition, so no new reserved-for entries beyond what `03-UI-SPEC.md` already declared for the Hero
- Favicon glyph (`favicon.svg`/`favicon.ico`/`apple-touch-icon.png`): the `>_` mark itself renders in `#00f0ff` (D-09) — the one non-DOM usage of this color, since favicon assets are static image files, not live CSS-driven elements

**New (non-accent) color usage this phase:**
- Favicon background: transparent for `favicon.svg`/`favicon.ico` (adapts to any browser-chrome color, light or dark tab bar) — `apple-touch-icon.png` alone gets a solid `#0c0e12` (`surface-container-lowest`) fill behind the glyph, because iOS does not honor PNG transparency on home-screen icons (it composites onto a system-chosen background otherwise, producing unpredictable contrast) — this is the one deliberate exception to "transparent by default," scoped to that single asset only.

Supporting neutral tokens (`on-surface-variant`, `outline-variant`, `white`) reused verbatim from the existing `@theme` — no new colors needed this phase.

## Layout & Structure Contract

*(Supplementary section — this phase's deliverables are new static/head-level artifacts rather than new content sections, so the fixed template categories above don't fully capture the composition. All patterns below resolve CONTEXT.md's decisions D-01–D-14 into concrete, ready-to-implement specs.)*

### 404 page (A11Y-02, D-05–D-08)

Full `Base` layout — real `<Nav />` (all four `#dossier`/`#stack`/`#projects`/`#contact` anchors intact, D-08) and `<Footer />`, zero special-casing. A single centered panel, reusing the Contact section's exact visual treatment (glass-panel + border-glow-cyan + rounded-xl) rather than inventing a new container style:

```astro
<Base
  title="Página não encontrada — [Nome/Marca Aqui]"
  description="A rota solicitada não existe neste sistema."
>
  <section class="min-h-[60vh] flex flex-col items-center justify-center text-center glass-panel border-glow-cyan rounded-xl p-12 max-w-2xl mx-auto">
    <p class="font-mono-label text-mono-label text-primary-container uppercase tracking-widest mb-4">
      &gt;_ ERRO 404 — ROTA NÃO ENCONTRADA
    </p>
    <h1 class="font-headline-md text-headline-md text-white mb-8">
      O sistema não localizou este caminho.
    </h1>
    <a
      href="/"
      class="btn-primary bg-primary-container text-on-primary-container font-mono-label text-mono-label uppercase tracking-widest px-8 py-4 rounded transition-all duration-300 cursor-pointer active:scale-95 inline-flex items-center gap-2"
    >
      VOLTAR AO INÍCIO
    </a>
  </section>
</Base>
```

No icon on the CTA (unlike the Hero's `VER PROJETOS`, which pairs with `arrow-forward`) — D-07 scopes this page to typography-only primitives, and a bare text button reads correctly against the terse, single-panel composition. `rounded-xl` (not the Contact panel's own radius — confirm against `index.astro` line 186, which also uses `rounded-xl`) keeps this visually identical to the Contact panel's corner treatment.

### OG template page (SEO-02, D-01–D-04)

`src/pages/og-template/index.astro` — **not** a page a visitor ever sees or navigates to; exists solely as a fixed-viewport screenshot target for `scripts/generate-og-image.mjs`. Composition reuses the Hero section's real classes verbatim (D-02) — grid background (`bg-grid-pattern`), both glow-cloud divs, `.glass-panel` framing, availability-badge treatment, title-line treatment — rendered inside a `1200×630` container, reading live from `site.brand`/`site.title` (D-01) so the image never drifts from `site.ts`'s actual placeholder/real content. Must NOT extend the normal `Base` layout (it needs no Nav/Footer/skip-link) — a standalone `<html>`/`<body>` wrapping just the visual composition, with:
```html
<meta name="robots" content="noindex" />
```
in its own `<head>`, and excluded from `@astrojs/sitemap`'s output via the integration's `filter` option (RESEARCH.md Pitfall 3 — this is a build-tooling/config change, not part of this UI-SPEC's visual contract, but flagged here so the planner doesn't lose it).

One shared image serves both `/` and `/404` (D-03) — `Base.astro`'s `ogImage` prop defaults to `/og-image.png` for every page; the 404 page does not override it.

### Favicon (SEO-05, D-09–D-10)

The mark is the `>_` glyph already used in the Hero's availability badge (D-09) — rendered as a genuine vector shape (a `>` chevron followed by a short horizontal underscore bar), not literal text characters, since favicons must remain legible as a pure silhouette at 16×16px. Single color: `#00f0ff` (`primary-container`), no gradient/glow effects (glow blur doesn't survive rasterization at favicon scale — a flat, high-contrast glyph is the correct choice here, not a literal port of the Hero badge's `box-shadow`-based glow).

Three files (D-10, matching the RESEARCH.md "State of the Art" 3-file 2026 baseline):
- `favicon.svg` — primary modern icon, transparent background, scalable
- `favicon.ico` — legacy fallback, 16×16/32×32/48×48 multi-resolution, transparent background
- `apple-touch-icon.png` — 180×180, **solid `#0c0e12` (`surface-container-lowest`) background** (the one non-transparent exception, iOS home-screen convention — see Color section above)

`Base.astro`'s `<head>` gains standard favicon `<link>` tags referencing all three (exact `<link rel>` values are a technical/markup detail for the planner, not a visual-contract decision).

### Meta tags (SEO-01/02, Pattern 1 from RESEARCH.md)

`Base.astro`'s `Props` interface gains `description` (required, no default — every page must pass one explicitly per SEO-01), `ogImage` (optional, defaults to `/og-image.png`), `ogType` (optional, defaults to `"website"`). This is a `<head>`-only change — no visible UI impact on either page's rendered body. Meta-tag field-to-copy mapping is fully specified in the Copywriting Contract above; exact `<meta>`/`<link>` tag markup is RESEARCH.md Pattern 1, unchanged.

### Decorative-icon `aria-hidden` pass (A11Y-03, D-11/D-12)

No visual change — pure accessibility-tree attribute additions to already-rendered Phase 3 elements:
- `index.astro`: Hero CTA's `Icon name="material-symbols:arrow-forward"` gains `aria-hidden="true"` (the `<a>` already carries the visible "VER PROJETOS" text — the icon needs no separate announcement)
- `index.astro`: Project-card fallback `Icon name="material-symbols:code"` (inside `.cover-fallback`) gains `aria-hidden="true"` (purely decorative; real cover photos already have descriptive `alt` text from Phase 3, this is the fallback-only icon)
- `Base.astro`: both `<div class="glow-cloud-top-right">` / `<div class="glow-cloud-bottom-left">` gain `aria-hidden="true"` (atmospheric, non-content, Z-Axis Level 1 per DESIGN.md)

**Explicitly NOT touched (D-13):** Tech-stack badges (`[ ASTRO ]` style) and Project tag pills stay exactly as Phase 3 left them — real visible `<span>` text, no `aria-label` rewrite. The Project "Live"/"Repo" link icons (`open-in-new`/`code`) are **not** purely decorative (they sit inside a labeled link but reinforce distinct link types visually) — CONTEXT.md's D-11 list is a closed, explicit set (Hero CTA arrow + card fallback icon); do not extend `aria-hidden` beyond it without a corresponding decision.

### Contrast verification (A11Y-04) — informs, does not change, this UI-SPEC

No new visual/color decisions are introduced by A11Y-04 — it verifies the *existing* Phase 1–3 palette against the *actually rendered* glassmorphism panels. RESEARCH.md's Pitfall 5 hand-computation already confirms every text/background pairing in the current design clears WCAG AA (`btn-primary` text: 4.58:1, tightest margin; `on-surface-variant`-on-glass-panel: ~10.5:1; `primary-container`-on-glass-panel: ~12.6:1). This UI-SPEC does not authorize changing any token to "fix" a contrast issue — if `scripts/verify-a11y.mjs` (D-14) finds a real violation against actual rendered pixels, that is a signal to return to this document and CONTEXT.md for a token-level decision, not something the checker or executor should silently patch around.
