## Phase Goal

**As a** technical recruiter (or a search-engine crawler), **I want to** find this portfolio in search, see a proper preview when its link is shared, and navigate it without accessibility barriers, **so that** the site earns technical trust before a single project description is read.

This plan makes the discoverability half of that story durable: a regression in any SEO artifact breaks the build instead of quietly shipping.

<interfaces>
<!-- The gate-script contract every verify-*.mjs in this repo implements. Follow it exactly. -->

1. Shebang, then an up-front block comment declaring the requirement IDs gated, the
   dependency policy, and the literal summary-line format.
2. Guard: if dist/ (or a required entry file) is absent, print a fixed message and
   exit 1 immediately — the RED state before any build has run.
3. Accumulate into `const violations = []` via `addViolation(check, detail)`; never exit
   on the first failure.
4. Print each violation to stderr as `verify-seo: <check> — <detail>`.
5. Print exactly ONE summary line to stdout, then exit 0 only when violations is empty.

Artifacts present in dist/ after plans 04-01 and 04-02:
  dist/index.html              home page (title, description, canonical, OG/Twitter, favicon links)
  dist/404.html                custom 404 (its own title + description)
  dist/og-template/index.html  internal screenshot route, carries meta robots=noindex
  dist/sitemap-index.xml       sitemap index
  dist/sitemap-0.xml           url set — exactly one loc, no og-template, no 404
  dist/robots.txt              User-agent line, Allow line, absolute Sitemap line
  dist/og-image.png            1200x630 share preview
  dist/favicon.svg   dist/favicon.ico   dist/apple-touch-icon.png

`site` value in astro.config.mjs (the single origin every absolute URL must use):
  https://portfolio-felipe-salles.example

PNG dimensions without a dependency: bytes 16..19 big-endian = width, 20..23 = height
(IHDR chunk follows the 8-byte PNG signature and the 8-byte chunk header).
ICO embedded-image count without a dependency: little-endian uint16 at byte offset 4.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gate script → developer confidence | A gate that passes vacuously is worse than no gate: it converts an unverified claim into a believed one |
| astro.config.mjs → gate expectations | The gate derives its expected origin from config, so a config change silently redefines what "correct" means |
| dist/ → public crawlers | The gate is the only automated thing standing between a sitemap/robots regression and a live crawler |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Tampering | `scripts/verify-seo.mjs` passing vacuously when artifacts are missing or checks silently no-op | mitigate | Hard dist/ and per-file guards that exit 1 before scanning; per-group ok/fail flags in a single summary line; six required negative mutations in the acceptance criteria prove each group can actually fail. |
| T-04-03-02 | Information Disclosure | A future sitemap/robots change re-exposing the internal `/og-template/` route to crawlers | mitigate | The `sitemap` group asserts no `<loc>` contains `og-template`; the `ogtemplate` group asserts the route still declares `noindex`. Both run on every `npm run verify`. |
| T-04-03-03 | Spoofing | Relative or wrong-origin `og:image`/`og:url`/canonical values causing unfurlers to fetch an unintended origin once deployed | mitigate | The `og` and `meta` groups require every such URL to start with the origin read live from astro.config.mjs, so the Phase 5 domain swap updates gate and site together instead of drifting apart. |
| T-04-03-04 | Tampering | Weakening the gate to make a build pass | mitigate | Task 2 states explicitly that a failing pre-existing gate must be fixed at the cause, with the single already-authorized exception being plan 04-01's narrow `rel="canonical"` allowlist. |
| T-04-03-SC | Tampering | npm/pip/cargo installs | accept | This plan installs no packages and the gate uses only Node builtins, so it adds zero supply-chain surface. |
</threat_model>
