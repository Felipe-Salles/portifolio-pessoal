# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope reminder:** Phase 1 renders **no new UI**. Its job is to mechanically wire the already-approved `Arquivos de design/DESIGN.md` tokens into Tailwind v4's `@theme`, self-host fonts/icons, and scaffold the `projects` Content Collection schema against one placeholder entry. This UI-SPEC therefore locks the **token translation contract** (source values → Tailwind theme names) rather than inventing new visual decisions. All values below are pre-populated from `DESIGN.md` (canonical frontmatter) and `code.html` (the prototype's working `tailwind.config`, confirming exact Tailwind key names to reproduce), plus `01-CONTEXT.md` decisions.

## Spacing Scale

DESIGN.md declares a project-specific named scale (base unit 8px) rather than the generic GSD default — this is the pre-approved contract (LAY-02 requires exact fidelity), so it is reproduced verbatim as Tailwind `@theme` spacing tokens. All values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| `--spacing-unit` | 8px | Base rhythm unit; footer vertical padding (`py-unit`) |
| `--spacing-margin-mobile` | 20px | Mobile page/section horizontal margins (`px-margin-mobile`) — LAY-01 |
| `--spacing-gutter` | 24px | Desktop page horizontal padding, project card grid gap (`px-gutter`, `gap-6`/`gap-8`) |
| `--spacing-section-gap` | 160px | Vertical gap between major page sections (`space-y-section-gap`) — DESIGN.md "Generous Verticals" |
| `--spacing-container-max` (max-width, not spacing) | 1280px | `max-w-container-max` — page content max width |

Tailwind's default 4px-increment spacing scale (`p-1`, `p-2`, `gap-4`, etc.) remains available and in use throughout the prototype (e.g. `p-8` card padding, `gap-3` badge spacing, `gap-6`/`gap-8` grid gaps) — the named tokens above are additive extensions for the five project-specific values that don't map to a default Tailwind spacing step, not a replacement for the default scale.

Exceptions: `margin-mobile` (20px) and `section-gap` (160px) are intentionally outside the common 8/16/24/32/48/64 rhythm — both are explicit DESIGN.md values, not deviations to fix.

## Typography

DESIGN.md locks 7 named type roles (more than the generic 3-4 size / 2 weight guideline) — this is intentional: the type scale is a pre-approved design contract (LAY-02), and Phase 1's job is to reproduce it exactly as Tailwind `fontFamily`/`fontSize` `@theme` extensions, matching the exact key names already implemented in `code.html`'s prototype `tailwind.config` (`display-lg`, `display-lg-mobile`, `headline-md`, `body-lg`, `body-md`, `mono-label`, `mono-code`).

| Role | Size | Weight | Line Height | Letter Spacing | Font |
|------|------|--------|-------------|-----------------|------|
| `display-lg` | 72px | 700 | 80px (1.11) | -0.02em | Lexend |
| `display-lg-mobile` | 40px | 700 | 48px (1.2) | -0.02em | Lexend |
| `headline-md` | 32px | 600 | 40px (1.25) | -0.01em | Lexend |
| `body-lg` | 18px | 400 | 28px (1.56) | normal | Inter |
| `body-md` | 16px | 400 | 24px (1.5) | normal | Inter |
| `mono-label` | 14px | 500 | 20px (1.43) | 0.05em | JetBrains Mono |
| `mono-code` | 13px | 400 | 20px (1.54) | normal | JetBrains Mono |

Template-standard mapping (for checker's generic 4-role comparison): **Body** = `body-md` (16px/400/1.5) · **Label** = `mono-label` (14px/500/1.43, uppercase, wide tracking) · **Heading** = `headline-md` (32px/600/1.25) · **Display** = `display-lg` desktop / `display-lg-mobile` below `md` breakpoint (both 700 weight).

Deviation note: 4 distinct weights (400/500/600/700) and 7 sizes are used, exceeding the generic "2 weights / 3-4 sizes" heuristic. This is accepted because the scale is an already-approved external design contract (DESIGN.md), not a phase-local decision — reducing it would break LAY-02 fidelity in Phase 3.

Technical metadata convention (DESIGN.md "Typography" prose): all labels, tags, and code snippets use JetBrains Mono, uppercase text, wide tracking (`tracking-widest`) — reinforces the "control panel" aesthetic. Headings use Lexend with tight tracking. Long-form body text uses Inter.

## Color

60/30/10 split derived from DESIGN.md's Material-Design-style token set (frontmatter is canonical; the prose "Colors" section describes intent/rationale using simplified example hexes — do not use those simplified hexes for implementation).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#111417` (`surface` / `background` / `surface-dim`) | Page canvas, `<body>` background, all large empty space |
| Secondary (30%) | `#1d2023` (`surface-container`), `#282a2e` (`surface-container-high`), `rgba(20,27,34,0.6)` glass fill | Cards, nav bar, footer, glassmorphic panels (Dossier, Stack, Projects, Contact), tech badge backgrounds |
| Accent (10%) | `#00f0ff` (`primary-container`, "Electric Cyan") | See reserved-for list below — never applied as a general interactive-element color |
| Destructive | `#ffb4ab` (`error`) / `#93000a` (`error-container`) | Not used in v1 — no destructive actions exist in scope (no contact form, no delete actions per REQUIREMENTS.md "Out of Scope"). Token pair retained in the `@theme` palette for completeness/future-proofing only; do not wire to any component in this phase. |

Accent (`primary-container` #00f0ff) reserved for:
- Primary CTA button fill + 12px hover glow (`btn-primary`)
- Secondary/ghost button border + text
- Focus-visible ring/glow on all interactive elements (A11Y-01, Phase 2 scope but token must exist now)
- "Available for work" status dot + pulse animation
- Active/hover state on nav links and footer links
- `border-glow-cyan` accents (System Specs panel border, Contact panel border) — 1px cyan border + 4px outer blur
- Tech badge text tint on hover (`primary-container/10` background variant)
- Section logo wordmark (`SYSTEM.CORE`) text color

Supporting neutral tokens (on-surface, on-surface-variant, outline, outline-variant, secondary, tertiary, and their `-container`/`-fixed`/`inverse-*` variants) reproduce DESIGN.md's frontmatter 1:1 as additional `@theme` color entries — full list is the frontmatter block in `Arquivos de design/DESIGN.md` lines 3–50. All must be present in `@theme` even though most are not exercised until Phase 2/3 components consume them, since this phase's success criterion #2 is "DESIGN.md tokens are wired into Tailwind's `@theme` config and usable by any component."

Borders/shapes note (Elevation & Depth, Shapes sections of DESIGN.md, also needed for the `@theme` `borderRadius` extension this phase delivers): default border = `outline-variant` at low opacity (10%); glass panels = 12–20px backdrop blur + semi-transparent `surface-container-high`-family fill; radius scale = `sm` 0.125rem, DEFAULT 0.25rem, `md` 0.375rem, `lg` 0.5rem, `xl` 0.75rem, `full` 9999px (frontmatter `rounded` block — canonical over `code.html`'s slightly different working radius scale, since DESIGN.md is the source of truth per canonical_refs).

## Implementation Notes (Tailwind v4 `@theme` mapping)

Additive guidance for the executor, scoped strictly to this phase's deliverable (wiring tokens, not building UI):

- Colors → `--color-{name}` custom properties in `@theme`, one per DESIGN.md frontmatter color key, dash-cased exactly as shown (e.g. `--color-primary-container: #00f0ff;`, `--color-on-surface-variant: #b9cacb;`). This reproduces `code.html`'s `colors` object 1:1 as Tailwind v4 CSS-first theme vars — no `tailwind.config.js` needed.
- Typography → `--font-{role}` (font family) and `--text-{role}` (size + line-height + letter-spacing + weight, using Tailwind v4's tuple `@theme` syntax) per the 7 roles table above, matching `code.html`'s `fontFamily`/`fontSize` key names exactly so class names stay identical to the prototype (`font-headline-md text-headline-md`, etc.).
- Spacing → `--spacing-{name}` for the 4 named tokens (`unit`, `margin-mobile`, `gutter`, `section-gap`) plus a max-width utility/token for `container-max` (1280px).
- Radius → `--radius-{name}` per the `rounded` block (`sm`, DEFAULT, `md`, `lg`, `xl`, `full`).
- Fonts self-hosted via `@fontsource/*` imports (per D-01) — no `<link>` to `fonts.googleapis.com`/`fonts.gstatic.com` may exist anywhere in the output (SEC-01 gate for this phase).
- Icons via `astro-icon` `<Icon />` — no Material Symbols icon font `<link>` may exist anywhere in the output (SEC-01 gate for this phase).
- `coverImage` field in the `projects` Content Collection schema must use Astro's `image()` schema helper from this phase onward (typed correctly even though optional and unused until Phase 3, per D-05).
