<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → local build | Third-party package code executes during `npm install` and `astro build`. This is the only meaningful untrusted-input boundary in Phase 1. |
| build output → visitor browser | Anything referenced by `dist/` becomes a network origin the visitor's browser contacts. External origins here leak visitor IP/UA and add an availability dependency. |
| design prototype (`code.html`) → production source | The prototype legitimately contains external CDN/font tags. Copy-paste from it is the concrete mechanism by which SEC-01 would be violated. |

|-----------|----------|-----------|-------------|-----------------|

Task 1's gate fails the build output on any `fonts.g*.com` reference or absolute-URL `@font-face` src. |

| T-01-03 | Information Disclosure | Residual `<link rel="preconnect">` to an external origin — loads nothing visibly, so a DevTools Network scan misses it, but still performs a DNS/TCP handshake off-origin | mitigate | Task 2 drops both preconnect tags entirely; the gate explicitly matches `rel="preconnect"` and `rel="dns-prefetch"` with absolute URLs, which is why verification is a deterministic `dist/` scan rather than a manual browser check. |
