## Phase Goal

**As a** visitor (recruiter, client or peer) landing on Felipe's portfolio, **I want to** reach the site at a public HTTPS address whose browser-enforced security headers block framing, script injection and protocol downgrade, **so that** the site itself is the proof that its author takes technical security seriously.

This plan closes the pre-deploy half of that promise: nothing secret ships to the browser, and nothing carrying a known high-severity advisory is in the tree when the first deploy happens.

<objective>
Add the SEC-04 gates that must pass BEFORE the site goes live: a committed secret-hygiene scanner over the git index, `src/` and the deployable output, plus an `npm audit --audit-level=high` pre-deploy gate with any findings remediated.

Purpose: SEC-04 requires "nenhum segredo/API key exposto no client; `npm audit` sem vulnerabilidades conhecidas antes do deploy". This project defines zero env vars today, so both gates should pass on the first run — they exist as regression barriers, and they must be green before plan 05-03 pushes the repo public.
Output: one new gate script wired into `npm run verify`, one standalone `audit:ci` script, and a clean audit with any remediation documented.
</objective>

    Guard: if `dist/` is absent, print `dist/ not found — run npm run build first` and exit 1.

    Implement four independent check groups.

    Group `tracked-env`: run `git ls-files` via `execFileSync("git", ["ls-files"], { encoding: "utf8" })` and add a violation for every tracked path whose basename matches `^\.env` case-insensitively. If `git` is unavailable or the command throws, that itself is a violation named `tracked-env` — a silently skipped check is worse than no check.

    Group `gitignore`: read `.gitignore` and add a violation if it has no line equal to `.env`. This is the regression barrier that stops group `tracked-env` from becoming trivially satisfiable later.

    Group `src-env`: recursively scan every file under `src/` with extension `.astro`, `.ts`, `.tsx`, `.js`, `.mjs`, `.json` or `.md` for occurrences of `import.meta.env.<NAME>` and for `import.meta.env[` bracket access. Collect each referenced `<NAME>`. Add a violation for any name that is neither `PUBLIC_`-prefixed nor one of the Astro built-ins `MODE`, `PROD`, `DEV`, `BASE_URL`, `SITE`, `ASSETS_PREFIX`, `SSR`. Add a separate violation for any bracket access, since a computed key cannot be statically proven safe.

    Group `dist-tokens`: recursively scan every file under `dist/` with extension `.html`, `.js`, `.mjs`, `.css`, `.json`, `.xml`, `.txt` or `.svg` for secret-shaped content, reporting the file path and the matched pattern NAME only — never the matched value, so the gate's own output can never become the leak. Patterns: the literal prefixes `sk_live_`, `sk_test_`, `pk_live_`, `github_pat_`; a line containing `-----BEGIN` together with `PRIVATE KEY-----`; and the regular expressions `AKIA[0-9A-Z]{16}`, `AIza[0-9A-Za-z_-]{35}`, `ghp_[A-Za-z0-9]{36}`, `xox[baprs]-[0-9A-Za-z-]{10,}`, and `eyJhbGciOi[A-Za-z0-9_-]{5,}` for a JWT header. Count the files scanned.

    Print each violation to stderr as `verify-no-client-secrets: <check> — <detail>`, then exactly one summary line to stdout: `SECRETS SUMMARY tracked_env=<n> gitignore=<ok|fail> src_files=<n> env_refs=<n> unsafe_env_refs=<n> dist_files=<n> token_matches=<n> violations=<n>`. Exit 0 only when violations is empty.

    Then add `"verify:secrets": "node scripts/verify-no-client-secrets.mjs"` to package.json scripts after `verify:csp-hash`, and append ` && npm run verify:secrets` to the END of the composite `verify` chain. Preserve the existing prefix byte for byte; do not reorder, rename or remove any entry, and do not pull `verify:deploy` into the chain.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Information Disclosure | A future `.env` file or API key becoming tracked and then published with the repo | mitigate | `tracked-env` group scans the real git index via `git ls-files`, and the `gitignore` group asserts the `.env` ignore rule still exists so the first check cannot be trivially defeated |
| T-05-02-02 | Information Disclosure | A future `import.meta.env.SOME_SECRET` reference inlining a value into the client bundle | mitigate | `src-env` group requires every referenced name to be `PUBLIC_`-prefixed or an Astro built-in, and flags computed bracket access which cannot be statically proven safe |
| T-05-02-03 | Information Disclosure | A secret pasted into content, config or a component reaching `dist/` and then production | mitigate | `dist-tokens` group scans every text-bearing file in the deployable output for nine secret shapes, reporting only the pattern name so the gate output is not itself a leak |
| T-05-02-04 | Tampering | Supply-chain compromise via a malicious or vulnerable dependency, including dev-only tooling | mitigate | `audit:ci` runs `npm audit --audit-level=high` over the full tree with `--omit=dev` explicitly forbidden; findings follow a documented four-step remediation ladder ending in written justification, never a silent override |
| T-05-02-05 | Tampering | A dependency bump quietly regressing the build or invalidating the CSP hash | mitigate | Every remediation step re-runs `npm run verify`, which rebuilds and re-checks all nine gates including `verify:csp-hash` |
| T-05-02-SC | Tampering | npm/pip/cargo installs | accept | This plan installs no new packages; `npm audit fix` may bump existing versions, and any such bump is gated by a full `npm run verify` before it is accepted |
