## Phase Goal

ROADMAP Phase 3's `**Goal:**` line is not written in the three-slot user-story form, so it is quoted verbatim rather than restated as an invented story (same handling as plan 03-01):

> Visitor can read every core section of the portfolio — Hero, Dossier, Tech Stack, Projects, Contact — matching the prototype's visual design and reflowing correctly on mobile.

This plan delivers the second vertical slice: the two sections that answer "what can this person do" and "how do I reach them".

<objective>
Append the Tech Stack and Contact sections to `src/pages/index.astro`, and add the two placeholder copy fields the Contact section needs to `src/data/site.ts`.

Purpose: Tech Stack is the fastest signal a recruiter reads, and Contact is the page's only conversion point. Both are pure `site.ts`-driven static markup, so they land together as one slice. Building Contact on the same `site.socials` array the Footer already consumes (D-10) means v2's real-links swap is a single-file edit and the two surfaces cannot drift apart.
Output: an extended `scripts/verify-sections.mjs`, two new fields in `site.ts`, and a `src/pages/index.astro` whose sections read Hero → Dossier → Tech Stack → Contact.
</objective>
