# Phase 3 — UI Design Contract

>

## Typography

Reuses DESIGN.md's type roles, consolidated to comply with the project's hard typography budget (max 4 sizes / max 2 weights). This phase renders real UI (unlike Phase 1's infrastructure-only tokens), so the same enforcement Phase 2 applied to its footer (collapsing `mono-code` into `mono-label`, commit b16268c) applies here too — extended to also resolve the weight budget, since this is the first phase to render `display-lg`, `headline-md`, `body-md`, and `mono-label` simultaneously on one page.

| Role | Size | Weight | Line Height | Usage this phase |
|------|------|--------|-------------|-------|
| `display-lg` / `display-lg-mobile` | 72px desktop / 40px mobile | 600 (consolidated from the token's native 700 — see Consolidation note) | 80px / 48px | Hero H1 (`site.heroHeading`) — `md:font-display-lg md:text-display-lg` desktop, `font-display-lg-mobile text-display-lg-mobile` mobile-first |
| `headline-md` | 32px | 600 | 40px | All 4 section H2s (DOSSIER/TECH STACK/PROJECTS/Contact heading), Project card titles (`text-xl` size-override — see note below) |
| `body-md` | 16px | 500 (consolidated from the token's native 400 — see Consolidation note) | 24px | Hero paragraph (`site.heroSubtitle`, consolidated from `body-lg` — see note), Dossier bio paragraphs (`site.bio[]`), Project card descriptions (`text-sm` size-override — see note), Contact subtitle |
| `mono-label` | 14px | 500 | 20px | Availability badge text, Hero title line (`site.title`, uppercase/wide-tracking), Hero CTA text, System Specs heading + list items, Tech Stack category headings + badges, Project tag pills (`text-xs` size-override — see note), Project live/repo link text (consolidated from `mono-code` — see Consolidation note) |

Template-standard mapping (checker's generic 4-role comparison): **Body** = `body-md` · **Label** = `mono-label` · **Heading** = `headline-md` · **Display** = `display-lg`/`display-lg-mobile`.

**Consolidation note (this supersedes the phase's earlier "external contract" deviation — that reasoning was accepted for Phase 1's infrastructure-only tokens, but per Phase 2's precedent does NOT extend to phases that render real UI):**

- **Sizes: 7 → 4.** Two token-level substitutions bring the phase to exactly 4 distinct sizes (one per role — Display/Heading/Body/Label):
  1. `mono-code` (13px) is dropped entirely — every element that used it (availability badge, System Specs list items, Tech Stack badges, Project tag pills) now uses `mono-label` (14px) instead. Same fix Phase 2 already applied to the footer.
  2. `body-lg` (18px) is dropped entirely — the Hero paragraph now uses `body-md` (16px) directly instead of `body-lg`, same token every other paragraph in this phase already uses.
  - The `text-xl`/`text-sm`/`text-xs` Tailwind size-overrides on Project card title/description/tags are pre-existing, component-scale visual adjustments layered on top of the `headline-md`/`body-md`/`mono-label` tokens (exact same mechanism, not additional named sizes in the type scale) — same treatment already accepted for the title/description call sites.
- **Weights: 4 → 2.** After the size consolidation above, four weight values remain distinct per role (`display-lg` native 700, `headline-md` 600, `body-md` 400, `mono-label` 500). Two additional, surgical weight-overrides collapse this to exactly 2:
  1. **Heading group → 600.** Hero H1 drops from 700 to 600, joining `headline-md`'s existing 600 (section H2s and Project card titles are unaffected — they were already 600). At 72px/40px the H1 still reads unambiguously bold at 600 weight; the visual loss versus a literal 700 is minor at that scale. Markup: swap the H1's `font-bold` class for `font-semibold` — a Tailwind override layered on top of the `font-display-lg`/`font-display-lg-mobile` token, the exact same mechanism as the existing `text-xl`/`text-sm` size-override pattern. This does not touch Phase 1's shared `@theme` token definitions.
  2. **Text group → 500.** All `body-md` paragraph text (Hero subtitle, Dossier bio, Project descriptions, Contact subtitle) moves from 400 to 500, joining `mono-label`'s existing 500 (badges/tags/specs/CTA/links are unaffected — they were already 500). Markup: add a `font-medium` override alongside every `font-body-md` usage.
  - This mirrors Phase 2's own consolidation methodology exactly: when two roles must merge to hit the weight budget, keep the *more prevalent* value. Phase 2 kept `mono-label`'s 500 over `mono-code`'s 400; the same 500 wins again here for the same reason (many badge/label call sites vs. four paragraph call sites), and 600 wins over 700 because `headline-md` at 600 has far more call sites this phase (4 section headings + every Project card title) than `display-lg` at 700 (exactly one H1).
  - **Final tally: 4 distinct sizes (72/40, 32, 16, 14), 2 distinct weights (600, 500) — within both hard BLOCK thresholds. No unresolved exception is needed.**

**Prototype-fidelity corrections carried into this phase (same class of fix as Phase 2's nav-brand `font-bold` removal — RESEARCH.md's Patterns 1-4 predate this revision and still show the pre-consolidation classes; this UI-SPEC's Typography Contract above is authoritative):**
- Project card title uses `text-xl` as a Tailwind size-override layered on top of `headline-md` (`code.html` line 334) — shrinks the 32px `headline-md` token down to card-scale (20px), a real, intentional prototype pattern. Weight is unaffected by this revision (`headline-md` stays 600). Port verbatim: `class="font-headline-md text-headline-md text-white text-xl"`.
- Project card description uses `text-sm` as a size-override on `body-md` (`code.html` line 335), plus the new `font-medium` weight-override from the consolidation above. Port as: `class="font-body-md text-body-md font-medium text-on-surface-variant text-sm"`.
- Hero H1 must use `font-semibold` (NOT the prototype's/RESEARCH.md Pattern 1's `font-bold`) per the Heading-group weight consolidation above — a genuine correction to the literal markup, not a style preference.
- Hero paragraph, Dossier bio, and Contact subtitle each need a `font-medium` override added alongside their existing `font-body-md` class (Text-group consolidation). The Hero paragraph additionally needs its size token changed from `font-body-lg text-body-lg` to `font-body-md text-body-md` — RESEARCH.md Pattern 1's literal code still shows the pre-consolidation `body-lg` classes.
- RESEARCH.md Patterns 1-3's literal code shows `font-mono-code text-mono-code` in three places (availability badge, System Specs list items, Tech Stack badges) — correct all three to `font-mono-label text-mono-label` per the Size consolidation above.
- RESEARCH.md Pattern 4's Project tag pills use `text-xs font-mono-code ...` (a `text-xs`/12px size-override on top of the family/weight utility — same override class as the card title/description overrides, not a token-level size, so it stays as-is) — correct only the family/weight portion: `font-mono-code` → `font-mono-label`.

## Layout & Structure Contract

*(Supplementary section — this phase's core deliverable is porting 5 sections of structured content, so the fixed template categories above don't fully capture section-by-section layout. All patterns below are verified, ready-to-use code from `03-RESEARCH.md` Patterns 1-7 — this section locks them as the design contract, resolving every "Claude's Discretion" item CONTEXT.md deferred to this researcher.)*

### Visual hierarchy

Hero's H1 (`display-lg`, 72px desktop / 40px mobile — the single largest text on the page) is the page's **primary visual anchor**; everything else scales down from it, both in size and in reading order. Within each of the 4 subsequent sections (Dossier/Tech Stack/Projects/Contact), that section's `headline-md` H2 heading is the **secondary anchor**, marking where each section begins and re-establishing hierarchy after the Hero. Within the Projects grid specifically, the featured project card (`md:col-span-2` + `.border-glow-cyan`, D-06) is the **tertiary anchor** — the largest, most emphasized element inside that grid, deliberately subordinate to the "PROJECTS" H2 above it but dominant over the other (non-featured) cards sharing the same grid.

### `<main>` wrapper (resolves RESEARCH.md Open Question 1)

`Base.astro`'s current `<main id="main-content" class="relative z-10 pt-32">` has no horizontal-margin/max-width/section-rhythm wrapper. **Locked decision: add it directly to `Base.astro`'s `<main>` element**, matching the prototype's actual structure (`code.html` line 246) and avoiding future duplication when Phase 4's 404 page needs the same container:

```
<main id="main-content" class="relative z-10 pt-32 pb-section-gap px-margin-mobile md:px-gutter max-w-container-max mx-auto space-y-section-gap">
```

This is a one-line class addition to an existing element, not new nav/footer content — it does not violate CONTEXT.md's "does NOT touch the nav/footer shell" boundary (that boundary concerns Nav/Footer components' own content, not `<main>`'s layout plumbing). All 5 sections in `index.astro` render as direct children of this wrapper with no additional per-section margin/max-width wrapping needed.

### Section order & anchors

Hero (no `id`, first section) → Dossier (`id="dossier"`) → Tech Stack (`id="stack"`) → Projects (`id="projects"`) → Contact (`id="contact"`). Every `id`-bearing section carries `class="scroll-mt-32"` so the fixed nav doesn't cover the heading on anchor-jump — must match Phase 2's nav anchors exactly (already verified identical).

### Hero (HERO-01, HERO-02)

Three-level text hierarchy, top-to-bottom: availability badge → H1 (`site.heroHeading`) → title line (`site.title`) → paragraph (`site.heroSubtitle`) → CTA. Full markup: RESEARCH.md Pattern 1, with the corrections listed in the Typography section's "Prototype-fidelity corrections" above (CTA label "VER PROJETOS", H1 `font-semibold` not `font-bold`, paragraph `font-body-md text-body-md font-medium` not `font-body-lg text-body-lg`, availability badge `font-mono-label text-mono-label` not `font-mono-code text-mono-code`). Availability badge pulse: Tailwind's built-in `animate-pulse` utility on the dot span — zero custom CSS, zero JS (D-04).

### Dossier (DOSS-01, DOSS-02)

8/4 column split (`grid-cols-1 md:grid-cols-12`, bio panel `md:col-span-8`, System Specs panel `md:col-span-4`). Full markup: RESEARCH.md Pattern 2, with the Typography corrections above applied (bio wrapper gets `font-medium` added to `font-body-md text-body-md`; System Specs list items use `font-mono-label text-mono-label` not `font-mono-code text-mono-code`). Bio renders `site.bio[]` as one `<p>` per array entry; System Specs renders `site.systemSpecs[]` as label/value rows.

### Tech Stack (TECH-01, TECH-02)

Fixed 3-column category grid (`grid-cols-1 md:grid-cols-3`) — NOT a generic loop over arbitrary categories, exactly 3 fixed cards: Languages, Frameworks, Infrastructure, reading `site.techStack.{languages,frameworks,infrastructure}`. Full markup: RESEARCH.md Pattern 3, with badges using `font-mono-label text-mono-label` not `font-mono-code text-mono-code` (Typography correction above). Each tech renders as a monospace badge: `[ {TECH.toUpperCase()} ]`.

### Projects grid (PROJ-01–04, D-05–D-09)

Always 3 columns on desktop (`md:grid-cols-3`) regardless of entry count (D-05). Sort: `getCollection('projects')` split into `featured.sort(byOrder)` + `rest.sort(byOrder)`, concatenated featured-first (D-07). Featured cards get `md:col-span-2` + `.border-glow-cyan` (D-06); non-featured cards get `hover:border-primary-container/50`. Full markup: RESEARCH.md Pattern 4, with the Typography corrections above applied (card title `text-xl` override unchanged; card description adds `font-medium`: `font-body-md text-body-md font-medium text-on-surface-variant text-sm`; tag pills use `font-mono-label` not `font-mono-code`, keeping their existing `text-xs` size-override).

**Sparse-grid gap is intentional, not a bug:** a featured card leaves its row's trailing cell empty (CSS Grid's default `grid-auto-flow: row`, non-`dense`). Do NOT add `grid-auto-flow: dense` — it would reorder cards and violate D-07's featured-first visual contract. See RESEARCH.md Pattern 4's full explanation.

**Cover image (PROJ-04):** `<Image>` from `astro:assets`, only inside the truthy branch of `project.data.coverImage ? <Image ...> : <gradient fallback>` — never pass a possibly-`undefined` `src`. Styled `w-full h-48 object-cover` with `grayscale group-hover:grayscale-0` (photo-reveal hover, reserved for real photos per D-09).

**Gradient fallback (D-08, D-09) — locked concrete composition, resolving CONTEXT.md's discretion items:**

```html
<div class="cover-fallback w-full h-48 border-b border-outline-variant/30 flex items-center justify-center bg-linear-to-br from-primary-container/15 via-surface-container to-surface-container-high transition-all duration-500">
  <Icon name="material-symbols:code" class="cover-fallback-icon w-12 h-12 text-primary-container/60 transition-all duration-500" />
</div>
```

- Gradient direction: `bg-linear-to-br` (top-left → bottom-right) — **not** `bg-gradient-to-br` (Tailwind v3 syntax, renamed in v4; see RESEARCH.md Pitfall 1 — using the old name silently produces no gradient)
- Color stops: `from-primary-container/15` (subtle cyan tint, top-left) → `via-surface-container` → `to-surface-container-high` (neutral, bottom-right) — reuses existing palette tokens, no new colors
- Icon: `material-symbols:code` (generic "code" glyph — the same icon already used for Contact/Repo elsewhere, reinforcing the "developer artifact" visual language), `w-12 h-12` (48px), `text-primary-container/60` (60% opacity cyan, subdued so it doesn't compete with real cover photos elsewhere in the grid)
- **Hover treatment (D-09, subtle, not a full effect swap)** — add this new primitive to `global.css`:
  ```css
  .group:hover .cover-fallback {
    background-color: rgba(0, 240, 255, 0.03);
  }
  .group:hover .cover-fallback-icon {
    opacity: 1;
    transform: scale(1.08);
  }
  ```
  Effect: icon opacity lifts from 60% to 100% and scales up 8% (`scale-105`-equivalent), plus a barely-visible cyan wash overlays the gradient — noticeably "alive" on hover without approximating the reserved grayscale→color photo-reveal effect (D-09 explicitly reserves that specific effect for real photos only).

**External links (PROJ-03):** every `liveUrl`/`repoUrl` `<a>` carries `rel="noopener noreferrer"` unconditionally — applied per-link inline, not via a wrapper component (RESEARCH.md "Don't Hand-Roll" table — only ~6 external-link call sites total in this phase, a wrapper adds indirection with no DRY benefit at this scale).

- **Typography weight/size corrections** — see the Typography section's "Prototype-fidelity corrections carried into this phase" above (font weight/size class swaps needed relative to RESEARCH.md Patterns 1-4's literal, pre-consolidation code).
