# Phase 2 — UI Design Contract

> Visual and interaction contract for the site shell (nav, footer, skip link, page metadata). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: `src/layouts/Base.astro` additions only — nav bar, mobile full-screen overlay, footer, skip link. Does NOT cover Hero/Dossier/Stack/Projects/Contact section content (Phase 3). Nav links and the Connect button point at anchors (`#dossier`, `#stack`, `#projects`, `#contact`) that don't resolve to real sections until Phase 3 lands — that is expected per CONTEXT.md's phase boundary.

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 14px (`text-mono-label`, JetBrains Mono) | 500 | 20px | Desktop nav links, Connect button, mobile overlay links (uppercase, `tracking-widest`), skip link, footer copyright line, footer social link labels |
| Heading | 32px (`text-headline-md`, Lexend) | 600 | 40px | Nav brand wordmark (`site.brand`) — desktop and mobile, same size |
| Display | N/A this phase | — | — | No display-scale text in nav/footer; Hero's `display-lg`/`display-lg-mobile` is Phase 3 scope |

Only two font sizes (14px, 32px) and two font weights (500, 600) are declared for this phase, per the project's 2-weight typography budget.

**Correction to the prototype (nav brand weight):** `code.html` applies both `text-headline-md` (600 weight, from the token) AND an explicit `font-bold` (700) class to the nav brand wordmark simultaneously — a genuine conflict in the prototype markup. Per Phase 1's precedent ("DESIGN.md frontmatter is canonical over `code.html`"), the executor MUST use `font-headline-md text-headline-md` only, weight 600, and drop the redundant `font-bold` override.

**Correction to the prototype (footer text weight):** `code.html`'s footer uses two different mono treatments — `font-mono-label text-mono-label` (14px/500) for the copyright line and `font-mono-code text-mono-code` (13px/400) for the social link row. Carrying both into this phase would introduce a third distinct font weight (500 label + 400 body + 600 heading), violating the project's 2-weight-per-phase typography budget. This contract standardizes all footer text — copyright line and social link row alike — on `text-mono-label` (14px/500), matching the nav's existing label treatment, and drops the `mono-code` (13px/400) token from this phase entirely. `mono-code` remains a valid token in the broader design system for future phases (e.g. code snippets, tech-stack tags in Phase 3) — it is simply out of scope for Phase 2's nav/footer shell.

Mobile overlay links use the same `headline-md` size/weight as the nav brand (32px/600/Lexend) for large, centered tap targets per D-01 — plus `uppercase tracking-widest` utility classes layered on top for stylistic continuity with the desktop nav's mono treatment. This does not introduce a new type-scale token; it reuses `headline-md` verbatim.

## Interaction & Structure Contract

*(Supplementary section — this phase's core deliverable is interaction/structure, not visual polish, so the fixed template categories above don't fully capture it.)*

### Visual hierarchy
Primary visual anchor on the nav bar is the brand wordmark (top-left, `headline-md`, largest element in the shell); the Connect button is the secondary CTA anchor (top-right, accent-bordered ghost style, the only bordered element in the nav row). In the footer, the copyright line anchors the start position and the social link row anchors the end position — the footer has no single dominant focal element by design, consistent with its low-emphasis, low-contrast (`on-surface-variant`) role at the bottom of the page.

### Semantic landmarks (SEO-06, A11Y-01)
- `<html lang="pt-BR">` — already correct in `src/layouts/Base.astro`, do not regress
- `<nav aria-label="Navegação principal">` wraps the nav bar
- `<main id="main-content">` wraps the page's `<slot />` content (the skip-link target)
- `<footer>` wraps the footer band (implicit landmark, no extra `role` needed)

### Desktop/mobile breakpoint
- 768px (Tailwind's default `md:` breakpoint) — matches the prototype's `hidden md:flex` / `md:hidden` nav pattern and `global.css`'s existing `@media (max-width: 768px)` grid-pattern rule. Do not introduce a custom breakpoint.

### Nav bar (LAY-03)
- `position: fixed; top: 0; width: 100%; z-index: 50` (matches prototype: `fixed top-0 w-full z-50`)
- Surface: `bg-background/60 backdrop-blur-xl border-b border-outline-variant/30`, plus the prototype's ambient shadow `shadow-[0_0_15px_rgba(0,240,255,0.1)]`
- Inner row: `flex justify-between items-center`, horizontal padding `px-margin-mobile md:px-gutter`, vertical padding `py-4`, `max-w-container-max mx-auto`
- Desktop (`md:` and up): brand wordmark left, 4 section links + Connect button right, `gap-8` between links
- Mobile (below `md:`): brand wordmark left, single icon-only toggle button right (44×44px minimum hit target); section links and Connect button are hidden and only reachable via the full-screen overlay

### Mobile full-screen overlay (D-01 — vanilla JS only, no framework island)
- Trigger: icon-only `<button>` in the nav bar, `<Icon name="material-symbols:menu">` when closed
- On open: overlay renders `position: fixed; inset: 0; z-index: 60` (above the nav's `z-50`), `bg-background/95 backdrop-blur-xl`, `flex flex-col items-center justify-center gap-8`
- Close control: same button swaps its icon to `<Icon name="material-symbols:close">` and moves/stays reachable (top-right of the overlay, or in-place in the nav bar — implementer's choice, but it must remain visually and programmatically the same control, toggling `aria-expanded`)
- Overlay content: the 4 section links (headline-md scale, see Typography) + the Connect button (same ghost style as desktop), stacked vertically, centered
- Vanilla JS behavior (no Alpine/React/Vue island):
  - Toggle button click flips an open/closed state (e.g. a `data-state` attribute or class on the overlay element) and toggles `aria-expanded` on the button
  - While open: trap focus within the overlay (Tab/Shift+Tab cycle among overlay links + close control only)
  - `Escape` key closes the overlay
  - Closing (via close-button click, Escape, or clicking a link that navigates) restores focus to the toggle button
  - Body scroll should be locked while the overlay is open (e.g. `overflow: hidden` on `<body>`) since it's a full-viewport takeover
- No prototype markup exists for this state (per CONTEXT.md canonical_refs) — this section is the sole specification for it; do not search `code.html` for an overlay pattern

### Connect button (D-02)
- Real anchor: `<a href="#contact">Connect</a>` — not a `<button>`, not JS-inert
- Style: ghost — `px-4 py-2 border border-primary-container text-primary-container font-mono-label text-mono-label uppercase tracking-widest rounded` (Tailwind's bare `rounded` = DESIGN.md's `rounded.DEFAULT`, 0.25rem)
- Hover: `hover:bg-primary-container/10`, plus the shared `.btn-primary:hover` glow primitive from `global.css` if the ghost button is also given the `btn-primary` class — otherwise a lighter one-off hover per the prototype's exact class list (`hover:bg-primary-container/10 transition-all duration-200`)
- Appears both in the desktop nav bar and inside the mobile overlay (same markup/style, different container)

### Footer (D-03)
- `<footer>` band: `bg-surface-container-lowest w-full border-t border-outline-variant/20`, top margin `mt-section-gap` (only meaningful once Phase 3's sections exist above it — harmless now)
- Inner row: `flex flex-col md:flex-row justify-between items-center`, `px-margin-mobile md:px-gutter py-unit gap-4 max-w-container-max mx-auto`
- Left: copyright line (see Copywriting Contract), `font-mono-label text-mono-label text-on-surface-variant` (per the Typography table's footer weight-collapse correction above — not `font-mono-code`)
- Right: link row rendered from `site.socials` (D-03) — `flex gap-6 font-mono-label text-mono-label uppercase text-on-surface-variant` (same correction — not `font-mono-code`), each `<a>` uses `site.socials[i].href` and `site.socials[i].label` (not `.icon`; footer is text-style links, distinct from the Contact section's icon-circle treatment which is Phase 3 scope), hover `hover:text-primary-container transition-colors duration-300`

### Skip link (D-04)
- Markup: `<a href="#main-content" class="skip-link">Pular para o conteúdo</a>` as the very first focusable element in `<body>`, before the nav
- Default state: visually hidden off-screen (e.g. `absolute -translate-y-full` / clip technique — never `display:none`, which would remove it from the tab order)
- `:focus` state: becomes visible — `fixed top-4 left-4 z-[100]` (above the mobile overlay's `z-60`), styled as a glass panel with a cyan glow: `glass-panel border-glow-cyan px-4 py-2 rounded text-mono-label text-primary-container uppercase tracking-widest`

### Focus-visible glow (A11Y-01)
No `:focus-visible` treatment exists anywhere yet (the prototype is a static, non-interactive mockup with zero focus states). This phase must add one. Add to `src/styles/global.css` as a new global primitive (reusable by every future phase, not just this one):

```css
:focus-visible {
  outline: 2px solid var(--color-primary-container);
  outline-offset: 2px;
  box-shadow: 0 0 8px rgba(0, 240, 255, 0.4);
  border-radius: var(--radius);
}
```

This mirrors the existing `.border-glow-cyan` primitive's exact blur/alpha values (`0 0 8px rgba(0, 240, 255, 0.4)`) for visual consistency — same glow language, applied on `:focus-visible` instead of a static class. Verify visibility on: nav links, Connect button (both nav bar and overlay), mobile toggle, overlay links, footer links, and the skip link itself.
