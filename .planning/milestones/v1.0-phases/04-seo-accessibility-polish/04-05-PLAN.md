## Phase Goal

**As a** technical recruiter (or a search-engine crawler), **I want to** find this portfolio in search, see a proper preview when its link is shared, and navigate it without accessibility barriers, **so that** the site earns technical trust before a single project description is read.

Seven automated gates now prove the artifacts exist and are structurally correct. This plan closes the one question no gate can answer: do they actually look right.

<objective>
A single blocking human-verification checkpoint over this phase's three visual deliverables — the favicon, the OG share image, and the 404 page — plus the keyboard-focus behavior on the new page.

Purpose: `verify-seo.mjs` can prove `favicon.ico` holds three sizes and `og-image.png` measures 1200x630; it cannot judge whether the `>_` glyph reads as `>_` at 16px or whether the share preview is visually coherent. 04-UI-SPEC.md is the approved contract; this checkpoint confirms the built output honors it.
Output: developer approval, or a defect list that becomes gap-closure work.
</objective>

  <how-to-verify>
    Run `npm run build` then `npm run preview` and open the printed localhost URL. Then check each item:

    1. Favicon in the tab — look at the browser tab for the home page. The mark should read clearly as a cyan `>_` (a chevron followed by a short underscore bar), not a smudge, not a letter, not the default globe/Astro icon. Try both a light and a dark browser theme if convenient; the SVG is transparent and should work against either.
    2. Favicon as a bookmark — bookmark the page and check the mark in the bookmarks bar (this exercises the `.ico` fallback rather than the SVG).
    3. Share image — open `dist/og-image.png` at full size. Confirm: the dark background with the visible grid pattern; both cyan glow clouds; the glass panel framing; the availability badge with its cyan dot; the wordmark reading `[Nome/Marca Aqui]`; and the tagline below it. Confirm nothing is cut off at the 1200x630 edges and no text overflows the panel.
    4. Share image matches the site — put the OG image next to the live home page Hero. They should look like the same design system, per D-02.
    5. 404 page — visit the preview URL with a path that does not exist, for example `/nao-existe`. Confirm: the site's nav and footer are present; the cyan-bordered glass panel is centered; the label reads `>_ ERRO 404 — ROTA NÃO ENCONTRADA`; the heading reads `O sistema não localizou este caminho.`; and there is exactly one solid cyan CTA reading `VOLTAR AO INÍCIO`.
    6. 404 CTA — click `VOLTAR AO INÍCIO` and confirm it lands on the home page.
    7. 404 nav anchors — from the 404 page, click a nav link such as `DOSSIER`. Per D-08 it should navigate to the home page and scroll to that section.
    8. Keyboard focus on the 404 page — press Tab repeatedly from the top. Confirm the skip link appears first, then nav links, then the CTA, and that every focused element shows the visible cyan focus glow established in Phase 2.
    9. Mobile reflow of the 404 — narrow the window to roughly 375px wide and confirm the panel and CTA reflow without horizontal scrolling or clipped text.

    If any item is wrong, describe what you saw rather than fixing it yourself — a token or copy change would need to go back through CONTEXT.md/UI-SPEC per 04-UI-SPEC.md's A11Y-04 note.
